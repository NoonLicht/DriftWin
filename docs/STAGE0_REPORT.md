# Отчёт Этапа 0: гипотеза → результат

Среда: Windows 11 Pro 10.0.26200, Rust 1.99.1, `windows` 0.62.2, один десктоп без Precision Touchpad.
Прототипы: `cargo run --release -p dw-prototypes --bin <имя>`. Двигались только собственные окна.

| # | Гипотеза | Результат | Что меняет в плане |
|---|---|---|---|
| 1 | Win-хук глотает Win+клавишу; без маскировки отпускание Win открывает «Пуск» | **Работает** (`p01`, синтетический SendInput): без маскировки foreground → `Windows.UI.Core.CoreWindow`, с фиктивной клавишей VK 0xE8 перед отпусканием Win «Пуск» не открывается. Время внутри хука: среднее 36 мкс, макс 437 мкс | Приём подтверждён. На реальной клавиатуре и в других раскладках не проверено |
| 2 | `DeferWindowPos` с флагами из ТЗ | **Не работает**: `SWP_NOSENDCHANGING` и `SWP_ASYNCWINDOWPOS` дают `0x80070057` (`p03`) | Из §5.3 убрать эти флаги для пакета |
| 3 | Пакет перемещений 50 окон < 4 мс | **Не подтвердилось** для окон другого процесса: `DeferWindowPos` 50 окон ≈ 14 мс (p95 31), 100 ≈ 24 мс. Цикл `SetWindowPos`+`SWP_ASYNCWINDOWPOS|NOSENDCHANGING`: 50 окон ≈ 2,8 мс, 100 ≈ 5,2 мс | Двигать циклом async-`SetWindowPos`, а не `DeferWindowPos`. Цели окон — тестовые, нагруженные реальные приложения могут быть медленнее |
| 4 | Координаты ±30000 допустимы | **Работает с оговоркой**: окно держится до ±32767/−32768, дальше значение ограничивается (40000 → 32767) | Парковка в ±30000 безопасна; предел 16 бит подтверждён |
| 5 | Невидимые рамки: GetWindowRect vs EXTENDED_FRAME_BOUNDS | **Подтвердилось**, но только при PerMonitorV2: рамка ≈ 7–8 px слева/справа/снизу, 0 сверху. Без DPI-манифеста значения виртуализуются и неверны | Манифест PerMonitorV2 обязателен с первого дня; хранить видимый прямоугольник |
| 6 | `DwmRegisterThumbnail` в прозрачном оверлее | **Частично**: регистрация, `QuerySourceSize`, обновление dest-rect успешны, обновление ≈ 0,03 мс (p95 0,05). Реальную отрисовку **не подтвердил**: `GetPixel` с экрана не видит композицию DWM (вернул чёрный) | Нужна визуальная проверка (скриншот). Стоимость анимации зума — не проблема |
| 7 | Фокус через `SetForegroundWindow` ограничен; обход Alt/AttachThreadInput | **Не доказано** (`p06`). Обычный вызов вернул false; AttachThreadInput вернул true и окно получило фокус; вариант с Alt вернул true, но фокус не получило. В первом тесте «чужой» foreground не установился, результат ненадёжен | Нужен более чистый тест. Предварительно рабочий вариант — AttachThreadInput; по Alt — нет доказательств |
| 8 | UIPI блокирует управление окнами с повышенными правами | **Подтвердилось** (`p07`): no-op `SetWindowPos` на «Диспетчер задач» (`elev=true`) вернул ошибку, на 11 остальных окнах — успех | Режимы нормальный/elevated/uiAccess нужны; в трее показывать «не управляется» |
| 9 | Фильтр окон §5.1 | **Работает**: из окон рабочего стола отобрано 12 реальных. UWP-хост (`ApplicationFrameWindow`) в этой сессии не встретился | Различение UWP не проверено |
| 10 | Precision Touchpad виден как HID 0x0D/0x05 и отдаёт WM_INPUT | **Не проверено**: на этой машине тачпада нет (19 raw-устройств, PTP не найден). Регистрация `RIDEV_INPUTSINK` прошла успешно, парсинг `HidP_*` скомпилирован, но не исполнялся на реальных отчётах | Нужен запуск `p02_touchpad` на ноутбуке с тачпадом |
| 11 | Системные жесты читаются из реестра | **Частично**: ключ `PrecisionTouchPad` есть, `AAPThreshold`=2, `ScrollDirection`=0; ключи 3/4-пальцевых жестов отсутствуют | Имена ключей из ТЗ не подтверждены; онбординг нельзя строить на них без проверки на ноутбуке |

## Не прототипировалось

Мышиный хук `WH_MOUSE_LL`, перехват Alt-Tab, защита от петель WinEvent, подавление запуска ярлыков Win+X,
полноэкранные игры, WGC-захват, несколько мониторов и разные DPI (проверялся один монитор).

## Статус сборки

`cargo build`, `cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings` — чисто;
`cargo test --workspace` — 2 теста `dw-core` (преобразование координат) проходят. Ничего не закоммичено.

## Этап 1 (клавиатура и мышь; жесты отложены в конец)

Реализовано: `dw-core::canvas`, `dw-win` (отбор окон, async-перемещение, baseline), `dw-input` (хук Win+Ctrl+стрелки,
аварийная Win+Ctrl+Shift+R), демон с треем и белым списком (`--only`/`--all`), страж, окна `fixture`.
Проверено вживую на `fixture.exe` (синтетический ввод): сдвиг камеры, аварийный возврат, возврат стражем после `taskkill /F`.
Не проверено: чужие реальные приложения, выход через трей, пауза/продолжение, мультимонитор, живая клавиатура.

## Этап 2: навигация

Реализовано (проверено юнит-тестами; вживую — см. «Не проверено»):

| Действие | Привязка |
|---|---|
| Сдвиг камеры | Win+Ctrl+стрелки |
| Панорама мышью с инерцией | Win+Ctrl + ЛКМ-перетаскивание |
| Фокус на ближайшее окно в направлении | Win+Alt+стрелки |
| Переключатель по MRU | Win+Ctrl+Tab / +Shift |
| Центрировать на окне в фокусе / домой | Win+Ctrl+C / Win+Ctrl+H |
| Закладки (якоря) | Win+Ctrl+1..9 перейти, +Shift запомнить |
| Автонавигация | при смене фокуса на окно вне экрана камера подходит к нему (`--no-auto-navigate` — отключить) |
| Закреплённые и виджеты | `--pinned exe,…` — закреплены на экране; `--widget exe,…` — остаются на холсте, но вне навигации |

Не проверено вживую: фокус на чужие окна (Alt-тап может на мгновение активировать меню приложения),
инерция мыши «на ощупь», закладки и MRU на реальных окнах. Закладки хранятся в памяти (сессия — Этап 6).

## Этап 3: конфиг и правила

Крейт `dw-config`: TOML-схема, привязки, правила окон, валидация с номерами строк; `driftwin --check-config`;
горячая перезагрузка; привязки хука подменяются на лету. Подробности и список нереализованных ключей — `docs/CONFIG.md`.
Проверено: 15 юнит-тестов конфига; `--check-config` (ошибка/предупреждения/нет файла); на окнах `fixture.exe` — правило
`size` (500x300, исходный размер вернулся после `taskkill /F` через стража) и горячая перезагрузка.
Не проверено вживую: пользовательские привязки с клавиатуры, `mod_key="alt"`, `toggle-pin-to-screen`, `close-window`,
правила `widget`/`pinned_to_screen`/`position` на реальных окнах, поведение при ошибочном конфиге на лету.

## Этап 4: привязка и кластеры

Чистая логика — `dw-core::snap` (без Win32, 12 юнит-тестов, включая псевдослучайную проверку «привязка не загоняет
окно в другое окно»): притяжка к краям соседей с зазором, выравнивание краёв/центров, `break_force` (окно отлипает при
рывке), кластеры по соседству, изменение размера с привязкой сторон и сдвигом присоединённых соседей, fit/fill,
`move-to-snap`. В демоне: перетаскивание окна мышью (Alt+ЛКМ, Alt+Shift — с кластером), изменение размера
(Alt+ПКМ — кластер сохраняется, Alt+Shift — одно окно; тянется ближайший угол), fit/fill по СКМ, действия с клавиатуры,
полноэкранный режим, прокрутка вида у края при перетаскивании (`edge_pan`) и курсором (`toggle-cursor-pan`), горячие углы.
Привязки мыши теперь настраиваются целиком (`[mouse.anywhere]`, три кнопки). Подробности — `docs/CONFIG.md`.

Проверено: 26 тестов ядра, 19 конфига, 2 ввода; clippy/fmt чисты; дымовой запуск демона на `fixture.exe` (окна взяты,
страж вернул их после принудительной остановки).
Не проверено вживую (ввод мыши/клавиатуры синтетически не подавался, чтобы не трогать рабочий ввод пользователя):
перетаскивание/resize/fit/fill на реальных окнах, `edge_pan`, горячие углы, `toggle-fullscreen`, поведение приложений
с минимальным размером окна. Известные ограничения: зум (`zoom-to-fit*`) не реализован, `toggle-fullscreen` не
убирает рамку окна, привязка работает только на основном мониторе, z-порядок при перетаскивании не меняется.


## Этап 6: обзор и фон

Сделано: крейт `dw-render` (оверлей GDI + `DwmRegisterThumbnail`), масштаб с анимацией, `zoom-to-fit`/`-snapped`/`zoom-in`/
`zoom-out`/`zoom-reset`, клик/перетаскивание/колесо/правый клик в обзоре, фон (сетка, цвет, плитка, обои), `[zoom]` и `[background]`
в конфиге и в окне настроек. Проверено вживую на окнах `fixture.exe` (скриншот экрана): сетка, живые миниатюры с содержимым
заголовков, подписи, масштаб 0,45. Гипотеза 6 из Этапа 0 («миниатюра реально рисуется в оверлее») **подтвердилась**.
Не проверено вживую: клик по миниатюре, колесо, перетаскивание, выход из обзора и посадка окон на места, `tile`/`wallpaper`,
`on_desktop`. Не сделано: мультимонитор (оверлей и фон только на основном), WGSL-шейдер, контуры других мониторов,
закреплённые окна в обзоре, мини-карта.


## Этап 7: сессия, заглушки, IPC

Сделано: `session.json` (версия, миграция v0→v1, карантин повреждённого файла, атомарная запись, `dw-core::session`),
заглушки (`dw-render::stub`, `suspend-window`, `suspend_on_close`, `restore_*`, запуск по пути и командной строке процесса,
сопоставление нового окна с заглушкой по AUMID/pid/потомку/имени, запуск UWP по AUMID, закрытие с панели задач без заглушки), IPC (`dw-ipc`: именованный канал с DACL, JSON-запросы, `Subscribe`),
`driftwinctl msg …`, `state.txt`. Заглушка — обычное окно верхнего уровня, поэтому участвует в привязке, кластерах,
навигации и обзоре без особых случаев.
Проверено вживую на `fixture.exe` (свой канал и каталог состояния): `suspend` → заглушка на том же месте и того же размера;
`relaunch` → новое окно встаёт на место заглушки; заглушки переживают перезапуск демона; `suspend_on_close` при `WM_CLOSE`
от самого приложения; `msg close` заглушки не оставляет; повреждённый `session.json` уходит в `.corrupt.<время>`; ответы
`state`, `cursor`, `camera --relative`, `zoom`, `bookmark --set`, `debug-counters`, ошибка для неизвестного действия.
Доработка: `screenshot` в режимах экран/`--all`/`--output`/`--region`/`--window` (PNG кодируется в потоке), `layout`
(список раскладок), монитор-камеры в `state` (точка мира в центре каждого из трёх мониторов проверена), `opacity`
(`WS_EX_LAYERED` включается и снимается), `subscribe` (9 снимков за 4 с при движении камеры), холодное восстановление из
`session.json` для приложения, которое не запущено (имитация перезагрузки), чтение AUMID у реальных окон (Настройки, Realtek,
Chrome) и запуск Калькулятора по AUMID с поиском его окна и цепочкой предков процесса. Тесты: 6 сессии, 6 IPC, 5 демона, новые
конфига.
Не проверено вживую: клик и Enter на заглушке (события приходят из оконной процедуры; ввод синтетически не подавался),
весь цикл «заглушка UWP → клик → окно встаёт на место» (куски проверены по отдельности), определение закрытия с панели задач
(эвристика по клику, клик не подавался), переключение раскладки (`layout next`/`prev` меняет раскладку окна пользователя — не
запускал), `subscribe` в течение долгого времени, настоящая перезагрузка ПК. Не сделано по замыслу: независимые камеры мониторов —
холст общий (в `state` у монитора своя точка мира, но двигается он вместе со всеми); `Mod+T`-подобные действия над заглушкой.
