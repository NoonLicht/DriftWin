# Конфигурация DriftWin (Этапы 3–4)

Файл: `%APPDATA%\DriftWin\config.toml` (или `--config путь`). Нет файла — стандартные настройки.
Проверка: `driftwin --check-config [--config путь]` (код выхода 0/1; ошибки с номером строки и столбца).
Горячая перезагрузка: демон раз в секунду сравнивает время изменения файла; также пункт трея «Перечитать конфиг» и
действие `reload-config`. Ошибочный конфиг не применяется, остаётся прежний.
Пример: [`config.example.toml`](../config.example.toml).

## Валидация
- Неизвестный ключ — предупреждение; неверное значение или диапазон — ошибка.
- Ключи из плана, которые ещё не реализованы, принимаются, но при явном задании дают предупреждение
  «пока не поддерживается».
- Комбинации без Win и без пары Ctrl+Alt отклоняются (иначе перехватывались бы Ctrl+C, Alt+F4 и т.п.);
  `Ctrl+Alt+Del` и `Win+L` отклоняются как системные. Клавиши сопоставляются по виртуальным кодам (раскладка не важна).

## Реализовано
| Раздел | Ключи |
|---|---|
| общее | `mod_key` (`super`/`alt`) |
| `[windows]` | `only`, `exclude` (`exe`, `class`), `max_fps` (0 — по частоте обновления мониторов, иначе 10..240), `panic_key` (`on_exit="restore_baseline"`) |
| `[navigation]` | `pan_step`, `camera_speed`, `mouse_speed`, `auto_navigate`, `bookmarks`, `nudge_step` (20), `resize_step` (20) |
| `[navigation.edge_pan]` | `zone` (100), `speed_min` (4), `speed_max` (10), `cursor_pan` (false), `cursor_zone` (20), `latency_ms` (120) |
| `[snap]` | `enabled`, `gap` (12), `gap_step` (4; `Win+]` / `Win+[` меняют зазор на лету до перезагрузки конфига, стоящие кластеры пересобираются под новый зазор, действия `snap-gap-increase` / `snap-gap-decrease`), `outer_gap` (12), `distance` (24), `break_force` (32), `corners` (true), `centers` (false) |
| `[zoom]` | только `fit_padding` (80) — отступ при `fit-window`; остальные ключи пока не работают |
| `[hot_corners]` | `threshold` (4), `top_left`, `top_right`, `bottom_left`, `bottom_right` = любое действие; основной монитор (по мониторам — с Этапом 6) |
| `[bindings]` | `disable_defaults = ["keys", "mouse"]` |
| `[keybindings]` | `"комбинация" = "действие"`, `"none"` отключает стандартную привязку |
| `[mouse.anywhere]` | `"комбинация+кнопка" = "действие"`; кнопки `left`/`right`/`middle`, нужен Win или Alt. Перетаскивание: `pan-viewport`, `move-window`, `move-snapped-windows`, `resize-window`, `resize-window-snapped`; по нажатию — любое обычное действие (окно под курсором), `none` отключает |
| `[[window_rules]]` | критерии `app_id` (exe), `class`, `title` (точно / glob / `/regex/`, без учёта регистра); поля `widget`, `pinned_to_screen`, `position`, `size` |

Правила применяются все подходящие по порядку: скаляры (`position`, `size`) — last-wins, булевы (`widget`,
`pinned_to_screen`) — sticky-on. Эффекты применяются при появлении окна; при перезагрузке конфига для уже открытых окон
пересматриваются только `widget`/`pinned_to_screen`.
`size` меняет размер видимого кадра; исходный размер сохраняется в `baseline.json` и возвращается при выходе и при аварийном возврате.

### Действия
`pan-viewport <dir>`, `focus-nearest <dir>`, `center-nearest <dir>`, `cycle-windows forward|backward`, `center-window`,
`focus-center`, `home-toggle`, `go-to-bookmark <1..9>`, `set-bookmark <1..9>`, `toggle-pin-to-screen`, `close-window`,
`reload-config`, `quit`, `none`. Направления: `up`, `down`, `left`, `right` (диагонали — позже).

Этап 4 (над окном в фокусе, при нажатии мышью — над окном под курсором):
`nudge-window <dir>` (на `nudge_step`), `move-to-snap <dir>` (к следующей точке привязки), `grow-window <dir>` /
`shrink-window <dir>` (сторона на `resize_step`, кластер сохраняется), `resize-to-snap <dir>` (сторона до соседа),
`fit-window` (под вид с отступом `fit_padding`), `fit-window-snapped` (то же, соседи сдвигаются), `fill-window`
(занять свободное место до соседей и краёв вида; повтор возвращает), `toggle-fullscreen` (окно на весь монитор;
выход — повтором или любым действием с холстом), `toggle-cursor-pan`. Повторный `fit-window*` тоже возвращает прежнее
состояние, пока окно не трогали.

### Стандартные привязки (`mod` = Win)
| Комбинация | Действие |
|---|---|
| `mod+ctrl+стрелки` | `pan-viewport` |
| `mod+alt+стрелки` | `focus-nearest` (при `mod_key="alt"` — `mod+ctrl+shift+стрелки`) |
| `mod+ctrl+tab` / `+shift` | `cycle-windows forward/backward` |
| `mod+ctrl+c` / `mod+ctrl+h` | `center-window` / `home-toggle` |
| `mod+ctrl+t` | `toggle-pin-to-screen` |
| `mod+ctrl+1..9` / `+shift` | `go-to-bookmark` / `set-bookmark` |
| `mod+ctrl+shift+r` | аварийный возврат (`panic_key`) |
| `mod+shift+стрелки` | `move-to-snap` (только при `mod_key="super"`) |
| `mod+f` | `toggle-fullscreen` |
| `mod+m` / `mod+shift+m` | `fit-window-snapped` / `fit-window` |
| `mod+shift+f` | `fill-window` |
| `mod+ctrl` + ЛКМ-перетаскивание | панорама с инерцией |
| `Alt` + ЛКМ-перетаскивание / `Alt+Shift` | переместить окно / окно вместе с кластером |
| `Alt` + ПКМ-перетаскивание / `Alt+Shift` | изменить размер, соседи сдвигаются (кластер сохраняется) / только это окно |
| `Alt` + СКМ / `Alt+Shift` + СКМ | `fit-window-snapped` / `fit-window` |
| `mod` + СКМ | `fill-window` |

При `mod_key="alt"` буквенные привязки получают дополнительный Ctrl (`mod+ctrl+f`, `mod+ctrl+m`, …), `fill-window` на
мыши — `mod+ctrl`+СКМ, а `move-to-snap` по умолчанию не назначен.

## Привязка и кластеры
- Во время перетаскивания окно притягивается к краям соседей (зазор `gap`, срабатывает на расстоянии `distance`);
  `corners` выравнивает края стоящих рядом окон, `centers` — центры. Чтобы отлипнуть, надо отвести окно больше
  чем на `break_force`. Привязка никогда не загоняет окно в другое окно.
- Кластер — цепочка окон, стоящих вплотную (с зазором `gap` ± 4 px и общим участком границы).
- Изменение размера тянет ближайший к курсору угол; в режиме кластера окна, присоединённые с этой стороны,
  сдвигаются на столько же.
- У края экрана при перетаскивании окна камера прокручивается (`edge_pan`), окно остаётся под курсором.
- Если приложение не приняло размер (минимум, фиксированный размер), через ~0,35 с берётся фактический.
- Исходный размер окна, которому менялся размер, сохраняется в `baseline.json` и возвращается при выходе.

## Принято, но пока не работает
`autostart`; `[decorations]`, `[effects]`, `[gestures]`, `[touch]`, `[outputs]`; в `[navigation]` — `trackpad_speed`, `touch_speed`, `drift`, `auto_navigate_on_*`, `nudge_step`,
`anchors`; `[outputs]` и горячие углы по мониторам; в `[windows]` — `elevated="notify"`, `park_limit`, `on_exit="bring_to_view"`,
`disable_when_fullscreen`; в правилах — `fullscreen`, `focus_on_open`,
`preserve_aspect_ratio`, `decoration`, `blur`, `opacity`, `border_*`, `corner_radius`, `shadow`, `output`, `pass_keys`,
`pass_mouse`, `layer_order`; действия `exec*`, `spawn`, `move-to-bookmark`, `send-to-output` и др. (§2.12 плана).
`toggle-fullscreen` растягивает окно на монитор, но стиль окна (рамку, заголовок) не меняет.
Мышь: `[mouse.on-window]`/`on-canvas`, `resize_on_border`, `decoration_*`.
Закреплённое окно пока не поднимается «поверх» остальных, а виджет не опускается «под» них.
Перезагрузка по mtime вместо `notify`.

`--only exe,…` (белый список), `--all` (явно все окна), `--config путь`, `--check-config`, `--state-dir путь`,

## Окно настроек

Значок DriftWin в трее: правый клик открывает меню, пункт «Настройки…» запускает `driftwin-settings.exe`
(лежит рядом с `driftwin.exe`; можно запустить и вручную: `driftwin-settings.exe [--config путь]`).

- **Общие** — все числовые, логические и выбираемые ключи конфига с диапазонами и подсказками; «Сбросить» убирает ключ из файла.
- **Клавиши** и **Мышь** — все действующие привязки (стандартные и свои): изменить комбинацию и действие, отключить,
  вернуть стандартную, добавить новую; клавишу можно записать нажатием (Win система окну не передаёт, поэтому `mod`/`Win` — кнопки).
- **Прочее** — правила окон, исключения и закладки (пока правятся в файле), кнопка «Открыть в Блокноте».

Сохранение проверяет файл тем же разбором, что и демон; при ошибках файл не меняется. Комментарии и порядок ключей
сохраняются (правка через `toml_edit`). Запущенный DriftWin подхватывает файл сам.


## Этап 6: обзор и фон

**Обзор (масштаб < 1).** Реальное окно нельзя уменьшить, поэтому при отдалении поверх экрана показывается оверлей с живыми
миниатюрами DWM; настоящие окна стоят на месте, пока вы не вернётесь к масштабу 1.0, и тогда встают на места камеры.
В обзоре окна не интерактивны: клик по миниатюре фокусирует окно и возвращает масштаб 1.0, перетаскивание пустого места
двигает вид, колесо меняет масштаб (точка под курсором остаётся на месте), правый клик — выход (камера возвращается, если вы
вошли через `zoom-to-fit`). Перемещение и изменение размера окон в обзоре отключены.

| Действие | Клавиши по умолчанию |
|---|---|
| `zoom-to-fit` — обзор всех окон; повтор возвращает камеру | `mod+w` |
| `zoom-to-fit-snapped` — обзор кластера окна в фокусе | `mod+shift+w` |
| `zoom-in` / `zoom-out` | `mod+ctrl+=` / `mod+ctrl+-` |
| `zoom-reset` — масштаб 1:1 | `mod+ctrl+0` |

`[zoom]`: `min` (0.1), `step` (1.25), `fit_padding` (80), `click` (`focus` — клик по окну в обзоре даёт ему фокус и центрирует вид, двойной клик выходит из обзора; `exit` — клик сразу возвращает масштаб 1:1); `backend = "capture"` пока не поддерживается.

`[background]`: `type` (`default`/`grid`, `solid`, `tile`, `wallpaper`, `none`; `shader` пока не поддерживается), `color`,
`grid_color` (`#rrggbb`), `grid_size`, `image` (PNG/JPEG/BMP для `tile` и `wallpaper`; пусто — обои рабочего стола),
`on_desktop` (рисовать фон и под окнами; эксперимент, скрывает значки рабочего стола).

Ограничения: обзор только на основном мониторе; закреплённые на экране окна в обзоре не показываются; окно, свёрнутое
или не отдающее картинку, видно как тёмная подложка с рамкой; z-порядок миниатюр не меняется при смене фокуса.
Для диагностики есть флаг `--start-zoom 0.4` (отдалить вид сразу после старта).


## Мониторы и изоляция

`[monitors] use = ["DISPLAY2", "DISPLAY3"]` — на каких мониторах работает DriftWin (имена показывает `driftwin --list-monitors`;
принимаются также `primary` и номер, `2` = `DISPLAY2`). Пусто — только основной монитор. Выбранные мониторы образуют один
общий холст: камера, обзор и привязка работают на их общем охватывающем прямоугольнике; оверлей обзора и фон рисуются на
каждом выбранном мониторе. Монитор, которого нет (отключён), игнорируется; если не осталось ни одного — берётся основной.
Список можно менять в окне настроек («Общие» → «Мониторы», карта мониторов) и на лету: конфиг подхватывается сам.

`isolate = true` (по умолчанию): окно, которое при движении холста перекрыло бы монитор вне списка, прячется далеко за
экранами, пока перекрывает его, и появляется снова, когда вид сдвинут назад. Окна, у которых центр на неуправляемом мониторе,
не берутся под управление, а окно, которое вы сами унесли на такой монитор, отпускается. Перетаскиваемое мышью окно при
перетаскивании не прячется.

Ограничения: у выбранных мониторов один общий вид (отдельной камеры на каждый монитор нет); при разных масштабах DPI
окна на границе мониторов могут менять размер средствами Windows; горячие углы и прокрутка у края считаются по внешней
границе общего холста.


## Окно у границы неуправляемого монитора

Окно, которое лишь частично заходит на неуправляемый монитор, не пропадает: настоящее окно паркуется за экранами, а на
управляемом мониторе вместо него показывается «призрак» — живая миниатюра той части окна, что лежит вне запретного монитора.
Выглядит как обрезка по границе, при этом рамка и содержимое остаются настоящими. Призрак не интерактивен: клик по нему
подводит вид к окну (и даёт ему фокус), после чего окно снова обычное. Окно, целиком лежащее над неуправляемым монитором,
просто прячется за экранами. (Обрезка областью окна `SetWindowRgn` отвергнута: она ломает рамку Win11 у Блокнота и других.)

## Частота кадров

`[windows] max_fps = 0` (по умолчанию) — частота обновления самого быстрого из управляемых мониторов (на 180 Гц — 180 кадров/с).
Кадры идут по таймеру высокого разрешения, скорость камеры не зависит от частоты кадров. Оверлей обзора не перерисовывается,
если ничего не изменилось.

## Этап 7: сессия, заглушки, IPC

### `[session]`
```toml
[session]
suspend_on_close  = false   # закрытие окна приложением оставляет заглушку
restore_windows   = true    # открытые окна после перезапуска возвращаются заглушками
restore_camera    = true
restore_bookmarks = true    # закладки, поставленные клавишами (set-bookmark)
```
В `[[window_rules]]` те же поля `suspend_on_close` и `restore_windows` работают для отдельных приложений (последнее правило побеждает).

### Заглушки
`suspend-window` (по умолчанию `Win+Shift+Q`) просит окно в фокусе закрыться (`WM_CLOSE`, мягко; ждёт до 8 с, если приложение
спросило «сохранить?»), а когда окно исчезло, ставит на его место и в его размер заглушку: имя приложения по центру и кнопка
закрытия `×`. Клик или Enter — запустить приложение заново («запускается…»); новое окно, появившееся у запущенного процесса
занимает место и размер заглушки. Окно признаётся «своим» по AUMID, по pid запущенного процесса или его потомка
(программа-пускатель вроде `code.exe` запускает настоящий процесс и выходит) — в течение 30 с; запасной вариант — то же имя
exe в первые 5 с. Если окно не
появилось за 30 с, заглушка снова «спит». Заглушку можно двигать, менять размер (не меньше 120×120), она участвует в
привязке, кластерах, навигации и обзоре; в Alt-Tab и MRU не входит; закрепить/развернуть на весь экран её нельзя. `×` или
`close-window` на заглушке просто убирает её.

`suspend_on_close`: закрытие окна самим приложением превращается в заглушку. `close-window` и `driftwinctl msg close`
заглушки не оставляют. Закрытие кнопкой на панели задач (или её миниатюры) Windows шлёт тем же `WM_CLOSE`, поэтому оно
определяется по косвенному признаку: левая кнопка была нажата на окне панели задач (`Shell_TrayWnd`, `TaskListThumbnailWnd` и
т. п.) не раньше чем за 2,5 с до исчезновения окна — тогда заглушка не создаётся. Это эвристика.
Запускается приложение по сохранённым пути к exe и командной строке (читается у процесса, `NtQueryInformationProcess`).
Упакованные приложения (UWP, Блокнот и Калькулятор из Microsoft Store; окна `ApplicationFrameHost.exe`) запускаются по AUMID
через `IApplicationActivationManager`; AUMID читается у окна (`System.AppUserModel.ID`). Надпись на заглушке у таких окон —
заголовок окна.

### `session.json`
`%LOCALAPPDATA%\DriftWin\session.json` (или `--state-dir`): версия формата, камера, закладки, окна и заглушки (приложение,
заголовок, путь, командная строка, AUMID, прямоугольник в мире). Пишется через ~1 с после изменения набора/положения окон и ~5 с
после панорамирования; запись атомарная (временный файл + переименование). При старте камера и закладки читаются до
сканирования; уже открытые окна с тем же приложением (сначала с тем же заголовком) возвращаются на сохранённые места, прочие
записи становятся заглушками (само ничего не запускается). Повреждённый файл переименовывается в `session.json.corrupt.<время>`
и старт идёт с пустой сессией; файл более новой версии обрабатывается так же. Формат v0 (без `version`) мигрируется.

### IPC и `driftwinctl`
Канал `\\.\pipe\driftwin-<SID пользователя>` (или `DRIFTWIN_PIPE`): DACL только текущему пользователю, сетевые клиенты
отклоняются, первый экземпляр создаётся с `FILE_FLAG_FIRST_PIPE_INSTANCE`. Однострочный JSON, запрос → ответ
`{"Ok":…}` / `{"Err":"…"}`. Селектор окна: число — `id` (HWND), строка — подстрока имени exe без учёта регистра
(в приоритете окно в фокусе).
```
driftwinctl [--json] msg camera X Y [--relative] | zoom L | focus W | move W X Y [--relative] | resize W w h
                          | opacity W v | pin W | close W | suspend W | relaunch W | layout [list|next|prev|N]
                          | cursor [X Y] | action "<действие>" | bookmark N [--set] | state | subscribe | debug-counters
                          | screenshot файл.png [--all | --output DISPLAY1 | --window W | --region X Y W H]
```
`subscribe` печатает снимок состояния при каждом изменении, не чаще 30 раз в секунду. `[ipc] expose_titles = false` убирает
заголовки окон из ответов. `layout` показывает раскладки клавиатуры (звёздочка — у окна в фокусе) и переключает раскладку окна
в фокусе. `screenshot` без параметров снимает мониторы под управлением (общий холст, как есть, вместе с оверлеями); `--all` — весь
виртуальный рабочий стол, `--output` — один монитор, `--region` — область в пикселях рабочего стола, `--window` — одно окно
(через `PrintWindow`, поэтому видно и окно за краем экрана или под другими, без невидимой рамки); PNG кодируется в отдельном
потоке и главный цикл не стопорит. В `state` у каждого монитора (`outputs`) `camera` — точка мира в его центре (холст общий, поэтому
независимых камер нет), `shared_camera` — камера холста, `position` — левый верхний угол монитора. Ограничения: `opacity` не трогает
окна с собственным слоем (`WS_EX_LAYERED`) и возвращается при выходе; `quit`/`exec` через IPC отдельно не ограничиваются — канал доступен лишь тому же пользователю.

### `state.txt`
`key=value` примерно 10 раз в секунду (только при изменении): `camera_x`, `camera_y`, `zoom`, `windows`, `suspended`, `focused`,
`focused_app`, `active_bookmark`, `paused`.
